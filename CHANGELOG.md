# Ledung changelog

For the person using Ledung. Newest first. One `## YYYY-MM-DD` heading per day (Ledung has no version
numbers, and releases are per machine), then TERSE `- ` bullets: one short line per change, plain words
saying what changed for the user, no prose paragraphs and no mechanism (that belongs in the commit
message). Each bullet ends with the issue number(s) it closes, `(#12)` or `(#12, #15)`, or `(no issue)`
when there is none, so the omission is deliberate. A PR that changes what Ledung does adds its bullet
under today's date, creating the heading at the top if it is missing; the pre-push check refuses a push
that changes `src/`, `web/` (not `web/dist/`) or `scripts/` without one (a commit trailer `Changelog: none` says there
is nothing user-facing in it).

## 2026-10-27
- Ledung's database no longer grows by gigabytes. Screenshots in tool output are no longer stored (the conversation still shows `[image]`), and tool output over 64 KB keeps only its start, with a note saying how much was cut. 14 days after a session ends, its tool output is cut to its first lines (`keepToolResultsDays` in the config). Conversations, questions, permissions and usage stay whole, and the full output is still in Claude Code's own transcript. The space comes back by itself. Once, at a start after the shrink has freed half the file, Ledung may take up to a minute to compact it before the page comes up; running sessions carry on. If it can't (too little disk, or another program has the database open), it says so and starts as usual. (#349)

- An account is now only a sign-in: Ledung no longer takes, keeps or passes a sign-in token, and moving a project to another account changes only whose plan and limits it uses; its conversations, memory, skills and settings stay as they are. Add an account and sign in to it once with Claude Code's own `/login`, using the command the page shows. Container projects can use accounts too, signed in inside the container (`~/.ledung-accounts/<name>`, or a mounted folder you name). An existing token account moves by itself, with no new sign-in: Ledung puts its token once into Claude Code's own sign-in store for the account, checks that Claude Code signs in with it, then deletes its own copy; until then Accounts says what it waits for (a stopped container, say). A place added later is signed in with `/login`. Removing an account removes its own sign-in here and in every container its projects ran in, and nothing else (not another account's, not the computer's own login), except where another login shares the folder. A login-folder account made before this keeps its sign-in, but its conversations, skills and settings from that folder no longer apply: sessions now use the Claude Code folder every session shares, and the old ones can still be opened with `claude --resume` and `CLAUDE_CONFIG_DIR` set to that folder. (#342)
- Sessions now run your own installed Claude Code, which Ledung needs at least the version its Agent SDK was built for. If it is missing or too old, a banner says how to install or update it, and sessions don't start until **Check again** finds it. **Settings → Claude Code** shows what new sessions run and what each running session uses. Container projects are unchanged. (#341)
- A project's **Name** field now suggests "e.g. Website". (#340)
- Ledung is licensed under the AGPL version 3, with a commercial license too. **Settings → About** says so, shows the running version and links to its **Source**; the first start says Ledung runs Anthropic's Claude Agent SDK and Claude Code, which are under Anthropic's own terms. (#332)
- When Claude Code isn't signed in, Ledung now says so at start and when you add an account: a banner tells you how to sign in (`claude` then /login, or an API key), with **Check again**. A session that has no login where it runs stops at once with the same steps instead of failing on its first message; a key in the project's own Claude Code settings counts, and if Ledung can't tell, the session starts with a warning. The check costs no tokens. (#333)
- Away mode has a third choice, **computer control** (off by default). It tells managers they may take over this computer while you are away, and their prompt line says so. Ledung doesn't check it. When you press Back, every manager is told at once, an idle one too. Managers also hear when the away time runs out or a change takes computer control away, if it was on. **Change…** sets the time or the choices while away, with no Back first. away_log shows when the last away period ran, how it ended and what was allowed. (#328)
